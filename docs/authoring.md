# 编写与验收约定

各版 `plan.md` 保留范围、实现边界和参考材料的验收记录。`参考状态：verified` 仅表示预写材料的检查记录；你的完成状态另见 [学习进度](progress.md)。不能把目录创建、阅读代码或参考重放成功当作你的实现完成。

每版从上一版的实际检查点开始：展示一个具体输入暴露的问题，运行朴素基线，做一个必要改变，再运行反例与正常用例。新增 helper 必须说明调用者、输入、返回值和副作用，不预建统一检索框架或兼容层。

每版正文包含场景、完整输入输出、精确文件目标、可执行命令、预期结果、故障实验及当前边界。最后汇总完整可运行检查点，不引入此前未讲解的逻辑。学习区的文件由读者在该版创建；已有 `fixtures/` 和 `tests/` 是输入与验收材料，不必提前复制未来实现。

验证覆盖正常、非法输入、失败、边界及代表性执行轨迹。检索任务必须使用固定样例和对应证据；模型相关测试记录模型版本、输入与实际结果，不能将随机输出当确定性断言。

正文目标为本版 `tutorial.md`；你的实现位于 `labs/<专题>/`，验收测试位于 `tests/`。预写代码及旧版快照位于 `reference/labs/`，快照专用检查位于 `reference/tests/`。普通学习命令只导入你的实现；参考重放必须显式选择参考区，见 [手动构建流程](learning-workflow.md)。

默认由你手写 `labs/` 的核心逻辑。AI 可以解释、评审、修改教程与参考材料；只有你明确要求代写某个练习时，才在学习区实现它。每版从你自己的上一版开始，在自己代码上通过检查、解释关键约束并完成失败实验后，才更新进度，按你的要求提交 checkpoint。参考快照不需要复制到学习区。

参考材料的验证记录不能充当教程从空白重建成功的证据；每次改写教学步骤，要在隔离目录按步骤重放。真实模型、生产身份系统和小样本容量外推仍明确列为边界。
