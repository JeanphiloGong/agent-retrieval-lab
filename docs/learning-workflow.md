# 手动构建流程

你要练习的是把约束和行为变成代码。`tutorials/` 是学习步骤，`labs/` 是你自己的实现；`reference/` 保存预写答案，方便卡住时对照。固定数据和测试已经提供，不需要重写一遍它们。

## 第一版从哪里开始

在仓库根目录执行 `uv sync --locked`，然后阅读 [01 v0](../tutorials/01-evaluation/v0/tutorial.md)。该版由你创建 `labs/__init__.py`、`labs/evaluation/__init__.py`、`labs/evaluation/validate.py`，先让合法标注通过，再故意破坏行号、引用和问题 ID，确认程序拒绝坏输入。只运行本版的 `tests/evaluation/test_validate.py`。

学习命令使用普通的 `uv run python -m labs...` 或 `uv run python -m pytest ...`，不设置指向参考区的 `PYTHONPATH`。没实现的模块应报导入错误；系统不会自动使用参考答案替你完成。

## 每版怎么推进

1. 确认本版前置：当前专题的上一版，以及依赖专题的指定版本。读本版问题和输入，先预测旧代码会怎样处理。
2. 在同一份 `labs/<专题>/` 上创建或修改本版文件。新包的 `__init__.py` 由你按教程创建；无须预建未来目录。先尝试实现，再用参考文件比较思路。
3. 运行正文中的行为检查与失败实验，再运行适用的验收测试。确认检查执行的是你的文件，而非参考文件。
4. 用自己的话解释输入、输出、关键约束和仍未解决的问题。在 [进度表](progress.md) 记录结果与命令，按需要保存自己的 Git commit，再开始下一版。

正文中的 `checkpoint` 可能指一份完整代码样例；`reference/labs/.../checkpoints/` 则是已准备的答案快照。你自己的版本历史用 Git 保存，不需要在 `labs/` 下复制全部答案快照。参考代码重放命令见 [reference/README.md](../reference/README.md)。

## 测试的使用边界

`tests/` 检查学习实现的行为，`reference/tests/` 只检查预写快照和课程材料。按正文选择测试文件或测试用例；不要在第一版就运行整个仓库。部分专题的现有测试在收集时就导入最终 API，只能在该专题组装完成后作为回归检查，不能用 `-k v0` 绕过缺失的未来接口。此类早期版本先运行正文给出的行为检查。

参考区会使用同一份 `tests/` 验证答案，因此“参考代码全部通过”只能证明材料可运行。它既不更新个人进度，也不能代替在你自己的上一版上检查新行为。

保存 checkpoint 前，检查 `git diff` 和 `git status`，只提交本版亲手实现的代码、相关材料及进度记录。你明确要求后，AI 可以协助检查和提交；参考区迁移本身不会替你创建学习完成记录。
